# 原油交易部与交易员执行能力架构

> 状态：v0.1 已注册并接入四机构竞技；玩家任命、滚动实测蛛网与独立执行指令对象尚未实现  
> 权威范围：交易部任命、六维执行能力、执行风格、冻结执行指令、成交偏差与 TCA 归因  
> 当前依赖：`oil_trading_strategy_v8`、观点失效、策略／公司两层风控、两个周执行窗口、动态价差、参与率滑点、费用返还、限仓与成交容量  
> 当前实现：连续六维能力、三维风格、Seed 候选 API、50分中性基准、周成交成本／完成／旧合约移仓映射与 TCA 已运行  
> 不属于当前事实：玩家可操作任命、持久存档、滚动实测蛛网和拆分后的独立执行指令对象尚未实现  
> 最近核对：2026-08-25

## 1. 设计结论

当前单品种流程已经把交易部负责人实现为独立任命档案，并接入四机构竞技。交易部不创造预测、不改变信号、不决定目标风险，只负责把已经合规的策略意图转换为实际成交，并对目标偏差和执行磨损负责：

```text
预测研究报告
→ 策略研究形成目标仓位与换手授权
→ 风控裁剪为合规目标
→ 交易部冻结执行指令
→ 两个周窗口按实现行情结算
→ 实际成交、仓位偏差、成本和执行成绩
```

交易部的核心价值不是提高方向收益，而是减少可避免的实施差额。坏预测配优秀交易员，只能更便宜、更完整地执行错误方向；好预测配较差交易员，则会因未成交、跨价、冲击和费用损失部分优势。

## 2. 部门边界

### 交易部可以决定

- 在策略授权范围内如何把订单分配到两个周执行窗口；
- 合理的被动／主动成交比例和执行紧迫度；
- 在公开成交容量内的拆分、完成与移仓协同；
- 可改善价差、滑点、软性经纪费用和已取得返还的实现质量；
- 未成交量、执行偏差和强制减仓的处理优先级。

### 交易部不得决定

- 预测方向、预测路径、策略信号或目标持仓；
- 策略允许的总换手预算、保证金预算和风险规模；
- 市场价格、公开成交量、市场持仓量、合约保证金率或限仓；
- 突破周成交容量、保证买在最低或卖在最高；
- 因未来实现行情有利而在结算时反向修改已经冻结的执行指令；
- 把未完成错误订单造成的偶然少亏记成交易员能力。

限仓整改、到期结算和正式风控强平优先于一切交易风格。执行能力只能改善市场允许范围内的结果，不能阻止硬性减险。

## 3. 六维能力蛛网

交易部蛛网表示能力，六维原则上都是越高越好，可以发布加权总分。它不同于无总分的策略偏好蛛网。每一维必须单独进入参数映射；总分只用于招聘、展示和事后分档，不得作为一个统一乘数直接修改全部成本。

| 字段 | 中文名 | 权重 | 现实／游戏含义 | 主要运行映射 |
|---|---|---:|---|---|
| `price_execution` | 价格执行 | 25% | 相对中性成交基准的价格改善／恶化 | 可避免跨价成本、执行价格偏差 |
| `impact_control` | 冲击控制 | 20% | 相同订单和参与率下控制市场冲击 | 参与率滑点系数 |
| `liquidity_scheduling` | 流动性调度 | 15% | 在两个周窗口间安排订单并利用可见流动性 | 周权重、集中度惩罚、剩余容量利用 |
| `completion_reliability` | 完成能力 | 15% | 在期限内完成合规订单，减少可避免未成交 | 完成率、未成交偏差、恢复执行 |
| `roll_coordination` | 换月协同 | 15% | 主次连双腿移仓时减少价差和残余风险 | 双腿同步、残余仓位、换月磨损 |
| `fee_efficiency` | 费用管理 | 10% | 管理经纪路径和已取得的返还资格 | 软性经纪费、返还实现率 |

```text
configured_total_score
= 0.25 * price_execution
 + 0.20 * impact_control
 + 0.15 * liquidity_scheduling
 + 0.15 * completion_reliability
 + 0.15 * roll_coordination
 + 0.10 * fee_efficiency
```

配置总分不能代替事后执行成绩。系统还应按已经完成的订单滚动形成 `measured_execution_radar` 和 `measured_total_score`；招聘时看到的是配置能力，长期评价看实现成绩。

## 4. 能力与执行风格分离

能力之外允许有三个不计总分的风格偏好：

| 字段 | 两端含义 | 约束 |
|---|---|---|
| `urgency` | 耐心等待 ↔ 果断抢量 | 只能在策略期限和成交容量内调整紧迫度 |
| `passive_preference` | 偏被动 ↔ 偏主动 | 当前基础映射作用于可避免跨价；未来盘口层再显式形成被动份额与排队风险 |
| `window_timing` | 前窗优先 ↔ 均衡／后窗保留 | 只能读取决策截点已经可见的历史流动性，不能读取未来两周 |

能力高低与风格没有必然关系。两个高水平交易员可以分别是“耐心低冲击”和“果断高完成”；风格决定取舍，能力决定同一取舍下做得多好。候选人由 Seed 生成并任命，不向玩家开放自由蛛网或参数滑杆。

## 5. 运行对象与数据流

### 5.1 `ExecutionDeskProfile`

稳定任命档案至少包含：

- `appointment.personnel_id`、`display_name`；
- 六维 `capability_radar` 与配置总分；
- 三维 `execution_style` 与能力标签；
- `profile_hash`、生成 Seed、配置／契约版本；
- 治理声明：不可编辑、不可改变市场、不可改变策略目标。

### 5.2 `ExecutionInstruction`

执行指令在半月开始、策略决策完成之后冻结。它读取：

- 当前市场和最近已经可见的周成交量／波动率；
- 策略输出的合规目标、计划净调仓、总换手预算与最低净优势；
- 当前持仓、费用滚动量和限仓状态；
- 已任命的交易部档案。

它发布：

- 每个合约、每个周窗口的净调仓预算和往返预算；
- 主动／被动份额、紧迫度和参与率上限；
- 强制整改、其它减险、新增风险的固定优先级；
- 可用的价差、冲击、完成、换月和费用能力参数；
- 截点、档案哈希、策略决策哈希和执行指令哈希。

### 5.3 `ExecutionSettlement`

结算推进到下一半月后，才允许读取两个新实现周的 OHLC 与成交量。它不得重新决定策略或修改指令，只计算：

- 市场可行成交与实际成交；
- 聚合买价、聚合卖价、未成交量和期末仓位偏差；
- 价差、滑点、费用、返还和换月磨损；
- 相对中性50分交易部的价值增减；
- 账户盯市、保证金和限额整改状态。

确定性执行偏差按 `world_seed + profile_hash + contract_id + week_serial + side` 寻址，不使用调用顺序随机数。长世界与短世界在相同截点必须给出相同执行指令和相同已实现结算。

## 6. 50分兼容基线与参数映射

所有能力映射以50分为中性点，逐字段精确复现 v0.6.0 中性执行器；接入后的交易策略版本为 v0.7.0。首轮只允许修改可避免成本，不改外部市场 owner。

建议的初始校准范围：

| 能力 | 0分 | 50分 | 100分 | 不可突破的硬边界 |
|---|---:|---:|---:|---|
| 价格执行：可避免价差乘数 | 1.35 | 1.00 | 0.75 | 总成本不得凭能力变成负数 |
| 冲击控制：滑点乘数 | 1.50 | 1.00 | 0.65 | 仍受参与率、波动率和75bps单边上限约束 |
| 流动性调度：集中惩罚乘数 | 1.35 | 1.00 | 0.70 | 不得使用未来周成交量或增加公开容量 |
| 完成能力：可避免漏单率 | 20% | 0% | 可恢复部分基线未成交 | 实际成交不超过价阶穿透和成交容量 |
| 换月协同：可避免腿风险乘数 | 1.50 | 1.00 | 0.60 | 到期清零和命名合约持仓恒等式不变 |
| 费用管理：软性经纪费乘数 | 1.20 | 1.00 | 0.80 | 交易所费、清算费、现金结算费不变；返还不超过已取得资格 |

高于50分的完成能力不是凭空增加成交。只有当前基线留下未成交、周内仍有价阶穿透且容量尚未用完时，才允许恢复其中一部分；达到硬上限时高分不再产生额外成交。

费用拆分固定为：

```text
hard_fee = exchange_fee + clearing_fee + cash_settlement_fee
soft_fee = broker_fee
net_fee = hard_fee + adjusted_soft_fee - eligible_rebate
net_fee >= 0
```

当前配置允许返还 exchange／broker 组件。交易部不得伪造滚动成交量或返还档位；`fee_efficiency` 只影响已经取得档位后的实现率和软性经纪费，不改变历史资格。

## 7. 执行偏差与 TCA 归因

交易员不能按账户总收益评价。每份回合报告必须同时保留四个价格／状态基准：

- `decision_arrival_price`：策略下达时价格；
- `neutral_market_execution_price`：当前50分执行器的周 OHLC4 聚合基准；
- `actual_raw_execution_price`：交易部能力作用后的原始成交价；
- `all_in_execution_price`：加上价差、滑点和净费用的现金等价价格。

最小归因：

```text
strategy_market_move
= neutral_market_execution_value - decision_arrival_value

desk_implementation_shortfall
= actual_all_in_value - neutral_market_execution_value

desk_value_added
= neutral_50_score_shortfall - actual_desk_shortfall
```

方向符号必须按买卖侧统一。市场方向移动归策略／市场，只有相对中性执行基准的可避免差额归交易部。未成交机会成本可以报告，但不能因为错误方向后来亏损而奖励拒绝执行；执行评分另以合规目标完成率和绝对仓位偏差约束。

每回合、每合约至少发布：

- 请求、可行、实际和未成交手数；
- 净调仓完成率、总换手完成率和期末目标偏差；
- implementation shortfall（美元、bps、美元／手）；
- 价差、冲击、费用、返还、换月与未成交偏差归因；
- 相对50分基准节省／多损失金额；
- 强制减仓缺口及连续整改回合；
- 六维本回合样本、滚动实测蛛网与实测总分。

## 9. 界面架构

交易部页面不放在市场行情内，属于机构管理：

```text
交易部
├─ 当前负责人：姓名、能力总分、风格标签
├─ 六维能力蛛网：配置能力／滚动实测切换
├─ 本年度执行成绩：shortfall、完成率、每手成本、节省金额
├─ 成本拆分：价差、冲击、费用、返还、换月
└─ 最近回合异常：未成交、限额整改、残余移仓
```

任命弹窗沿用研究机构与策略负责人的 Seed 候选方式。玩家选择人，不直接拖动蛛网。总分可用于快速比较，但必须同时显示风格和最近实测，避免把高总分误解为所有订单都更便宜。

1. **档案阶段（已完成）**：新增 profile/config/contract、Seed 候选和50分默认档案。
2. **成本阶段（已完成）**：接入价格执行、冲击控制和费用管理；50分逐字段兼容。
3. **完成阶段（基础完成）**：接入可见流动性调度与正常指令完成乘数，不改变硬容量；更细的价阶漏单恢复待后续。
4. **换月阶段（基础完成）**：旧合约退出腿已接换月磨损；完整主次连双腿同步与残余风险评分待后续。
5. **评分阶段（部分完成）**：已发布同订单相对50分基准的逐周／逐合约／逐回合 TCA；滚动实测蛛网和部门报告待后续。
6. **竞技阶段（已部分完成）**：玩家与3家 AI 已随机抽取交易部档案，并接入正式现金／保证金账户、追保强平和结算；仍需玩家任命、持久存档和长期能力成绩。

## 11. 验收门禁

- 50分档案逐字段复现中性成交、费用和盈亏数值；v0.7.0 因新增档案身份与 TCA 字段使用新的结果哈希；
- 能力分与风格均不得进入预测、信号、目标仓位、保证金预算或市场容量；
- 同一订单和市场下，价格／冲击／费用能力提升应分别单调降低对应可避免成本；
- 完成能力只能在未成交且仍有穿透和容量时增加成交；
- 强制减仓优先级不受风格影响，整改期间不得增加绝对风险；
- 原始成交价保持在实现周 K 可行范围内，all-in 价格与现金成本只记一次；
- 买卖、净调仓、总换手、仓位、价差、滑点、费用、返还和 PnL 恒等式继续逐层对账；
- 高能力交易部不能系统性挽救低能力预测的方向亏损；交易部差异应主要体现在 shortfall 与完成率；
- 跨 Seed 审计中，高换手策略对交易部能力更敏感，但交易员差异不得压过预测能力造成的主要方向差异；
- 长／短世界、服务重启和相同 Seed 任命保持确定性与前缀稳定。

首轮数值目标不是预设交易员带来固定收益，而是让0—100分在高换手账户上形成可观察且有界的执行成本差异。普通换手账户年化收益差异宜约0.5—3个百分点；若交易部能力轻易制造十几个百分点方向收益，说明它越权吸收了研究或策略能力。
