# 原油期货回合交易聚合设计

> 状态：单账户全成本引擎、跨回合观点失效、收益／换月归因、策略／公司两层风控、交易部能力、正式现金／保证金账户和四机构并行竞技已实现；短线单合约方向策略已重构为八维连续风格；投委会当前由系统代理执行审批与资金授权，可操作投委会和共享市场容量聚合仍是未来设计  
> 权威范围：玩家与 AI 的原油期货目标持仓、回合净额执行和交易报告  
> 当前依赖：只读 `oil_futures_overlay_v8`、半月回合、标准合约与参与者限额  
> 不属于当前事实：玩家自主目标／委托、正式持久存档、外部注资、动态组合保证金、机构间容量聚合和可选策略仍不存在  
> 最近核对：2026-08-26

## 设计结论

一个游戏回合代表半个月，不模拟逐笔委托簿。正式设计中，玩家与 AI 应对每个命名合约提交**带符号的目标持仓**，执行层把同一回合的多空意图净额化、应用限仓与成交额度并生成报告。当前竞技 Demo 已有四个独立账户，但目标由内置策略生成，各机构分别按公开容量执行；尚未把四家订单聚合成共享市场容量或互相撮合。

不为开仓和平仓设置两套成交额度，也不要求策略提交“开多／平多／开空／平空”类型。持仓从正数减少、从负数回升或跨越零点，都由当前持仓与目标持仓的差自然表达。

```text
当前持仓
→ 策略目标持仓
→ 单合约与组合限仓裁剪
→ 净增减需求
→ 每实体成交额度裁剪（当前）
→ 多实体共享容量聚合（未来）
→ 回合末持仓、现金和交易报告
```

## 部门架构与三类专业能力

原油交易长期扩展按预测研究、策略研究、风控审阅、投资决策、交易执行和账户硬规则组织。研究预测、策略偏好、风控偏好和交易执行都可以形成不同人才；投资决策负责审批与资金分配，账户层只执行不可协商的市场和结算规则，不能把这些职责压缩成一个总能力。

| 层级 | 唯一职责 | 人员／系统表达 | 当前成熟度 |
|---|---|---|---|
| 研究机构 | 预测方向、路径、振幅区间和期限结构 | 六维研究能力蛛网及事后实测评分 | 模型、API、评分和竞技后台已运行；预测 K 前台已撤下 |
| 策略研究 | 研究如何把已发布预测转成候选信号与策略授权 | 任命负责人后形成无总分的八维偏好蛛网 | 已有 Seed 候选名单、只读蛛网、参数映射与预测方向后端基线 |
| 策略风控 | 针对每项策略提出容量、波动、回撤、集中、流动性和移仓建议 | 策略八维压力 × 公司 CRO 六维无总分偏好形成独立审阅书 | 已实现；同一 CRO 面对不同策略会给出不同政策，偏好不代表能力 |
| 投资决策 | 审批策略风控和公司风控，并独立决定资金授权 | 投委会／组合分配器 | 当前由系统代理批准；资金授权已进入计算，尚无玩家操作 |
| 交易员 | 在容量允许范围内完成目标调仓，并形成回合聚合买价／卖价 | 六维能力总分＋独立执行风格＋实测 TCA | 已实现连续能力、候选、成本映射、TCA和竞技随机任命 |
| 公司风控 | 对组合总容量、总波动、总回撤、集中、流动性和移仓提出公司级要求 | 同一公司 CRO 的六维连续偏好；只允许缩小合规目标 | 已实现并接竞技；当前只有一个策略，组合效果待多策略放大；CRO 能力尚未建模 |
| 账户硬规则 | 执行限仓、可用资金、追保与强平 | 无风格的 `oil_futures_account_v1` owner | 已实现现金、保证金冻结、半月盯市、利息／融资、追保、强平与破产；持久化和组合保证金待实现 |

边界固定如下：

- 研究机构只发布信息，不读取玩家仓位，也不直接产生交易；
- 策略研究负责人只能形成策略授权，不得修改市场规则；玩家只能任命生成候选人，不能自由拖动蛛网；
- 风控部对策略与公司分别提出建议，不拥有资金，不得自行批准自己的建议，也不得制造或反转方向性仓位；
- CRO 六维蛛网只表达风险容忍取舍，不表达风险识别、压力测试或整改执行能力，也不得合成为“越高越好”的总分；
- 投资决策只能读取截点已经可见的市场、预测、策略授权、风险建议和账户，不得读取隐藏真实路径；投委会批准风险政策，同时独立决定每项策略可使用多少公司权益；
- 交易员只能执行合规目标，不得修改策略方向、突破限仓或改变模拟市场价格；
- 策略风控先裁剪单策略目标，公司风控再作为组合总闸门裁剪；账户硬规则最后执行市场限仓和成交容量；
- 研究总分、策略偏好、策略收益和交易员执行成绩分别评价。策略蛛网没有总分，不能用“越高越好”解释。

## 两类信号引擎、过滤器与组合器

策略是否独立，以利润来源是否发生实质变化为准。单合约方向策略中，顺势延续与区间回归不再伪装成两个完全独立的策略，而是同一引擎的连续光谱；只有同时持有不合约、主要赚取价差的期限结构相对价值才作为第二类引擎。

| 信号引擎 | 目标仓位来源 | 利润来源 | 当前状态 |
|---|---|---|---|
| 短线单合约方向 | 回归端读取预测中枢相对当前价格的偏离；延续端组合已可见的8周趋势和冻结2／8周预测路径 | 原油绝对方向，但可在延续—回归光谱上连续移动 | 已实现 `forecast_continuation_reversion_directional_edge_sized_turnover_v7` |
| 期限结构相对价值 | 比较主力／次主力或更远月的现行价差与预测价差变化 | 同时持有方向相反的多合约仓位，主要赚取曲线价差 | 未实现；当前双合约预测和期限字段足以支持 |

旧设计中的“预测偏差逆向”已经折叠为回归端的一类证据，不再单列。“突破确认”是延续端的过滤器，不是第三种利润引擎。“综合平衡”也只是未来的组合分配器。

```text
单合约方向／期限结构引擎
→ 突破／确认等过滤条件
→ 多策略组合分配
→ 统一风险参数
→ 统一换手和容量执行
```

战争事件、波动率衍生品和日内微观结构目前没有相应信息 owner，不进入首批策略目录。现阶段只运行已实现的短线单合约方向引擎，期限结构相对价值留待后续独立建模。

## 任命制策略偏好与换手

同一方向引擎“相信什么、做多少、做多快、何时做”由策略研究负责人八维偏好决定。服务只发布 Seed 生成的候选名单，不接受自由蛛网输入。八维分别为延续／回归倾向、资金部署倾向、调仓反应、入场选择性、换手活跃、持仓耐心、近月集中和预测期限；没有总分。

相关映射统一保存在 `oil_strategy_research` owner：延续／回归倾向在0—100分上连续插值，50分明确是30%延续／70%回归；资金部署倾向只决定投委会已分配权益中25%—75%可用于本策略，不再改写公开限仓。调仓反应、选择性、换手活跃、持仓耐心分别控制目标追踪／普通净成交、信号死区与净优势底线、往返交易预算、减仓保留；近月集中和预测期限负责合约及2／4／8周证据分配。

换手活跃只决定：

```text
gross_turnover_multiplier = 0.15 * 200^(turnover_activity / 100)
urgency_multiplier = 0.85 + 0.30 * turnover_activity / 100
```

它不再改变目标追踪、信号死区、最小价阶、净优势底线或仓位。后端仍保留 `turnover_intensity` 校准覆盖，但这不是玩家 API。研究机构配置总分和事后实测分也不得进入策略偏好、风险容量或目标仓位；错误预测继续通过实际盈亏暴露。

换手预算不是成交保证。所有风格仍按“限仓整改 → 其它减险 → 新增风险”的优先级执行，并受单合约限仓、组合总限仓、保证金容量、临时持仓空间和 `turn_trade_limit_lots` 共同裁剪。大仓位从净多翻到净空需要接近两倍原持仓的成交量，实际仓位可能经过减多、零仓和建空。

v0.6.0 在 v0.5.0 的周度总买卖账本、动态价差、参与率滑点、逐边手续费、滚动返还、净优势放量和限价穿透之上，新增任命制人员档案并拆开原单一换手旋钮。净调仓与往返交易成本和盈亏继续独立归因；不能只用总收益判定任何一维偏好的优劣。

## 已实现基线与下一步成交磨损

正式时间口径仍是半个月一回合，不改成月度回合。当前 v0.5.0 保留半月决策，在回合内拆成两个周执行窗口；周内不恢复逐笔委托，而是聚合记录总买入、总卖出、净调仓、往返手数、穿透成交、分类成本和盈亏：

```text
半月开始的市场、预测和仓位
→ 半月目标仓位与换手配置
→ 第1个周执行窗口
→ 只读第1周已实现结果
→ 第2个周执行窗口
→ 半月聚合成交、费用和盈亏报告
```

当前两个周设置均在半月开始时由已发布预测冻结，成交预算的两周权重也只读取截点前最近两根可见周成交量。预测方向性优势扣除可见成本与最低净优势后，冻结每周0—100%的往返预算使用率。实际周 K 只在结算时判断价阶穿透与部分成交；阳线使用 `开→低→高→收`、阴线使用 `开→高→低→收` 的确定性聚合路径。研究层如以后要在半月中途修订报告，必须另建有截点的 vintage，不得由执行层自行生成。

### 总换手与净调仓分离

高换手的核心不是把期末净仓位做得更大，而是允许同一仓位在两个周窗口内反复周转。每个实体、合约、周窗口必须同时记录：

```text
net_delta_lots = buy_lots - sell_lots
gross_turnover_lots = buy_lots + sell_lots
round_trip_lots = (gross_turnover_lots - abs(net_delta_lots)) / 2
ending_position_lots = starting_position_lots + net_delta_lots
```

例如期初和期末都维持10,000手净多，高换手算法仍可在回合内聚合买入100,000手、卖出100,000手，净调仓为0，总成交为200,000手。这些买卖必须发生在不同的可执行时点才记总换手；同一时点的内部子策略对冲先净额化，不得制造虚假成交和费用。

换手倍数不直接当作保证成交量，而是策略可用的总成交预算。初始校准范围可设为：

| 换手档位 | 半月总换手预算／参考净仓 | 周执行窗口 | 预期特征 |
|---|---:|---:|---|
| 低换手 | 0—1倍 | 1个 | 主要完成净调仓，尽量持有 |
| 中换手 | 1—5倍 | 1—2个 | 允许在两周间进行一次再平衡 |
| 高换手 | 5—30倍 | 2个 | 周内买卖聚合周转；10,000手持仓可对应50,000—300,000手总成交 |

这些倍数只是开发初值。净调仓仍受单合约限仓、组合限仓和保证金限制；总换手则另受每周公开成交量和实体参与率上限约束。必须拆分 `net_position_change_limit` 和 `gross_execution_limit`，否则既会误杀高换手，也可能让实体刷出超过公开市场容量的假成交。

毛预算不能在价阶触发后自动吃满。当前冻结公式为：

```text
net_edge_floor = strategy_selectivity_mapping  # 0.05%—0.225%
expected_net_edge = forecast_expected_edge - estimated_round_trip_cost
edge_quality = clamp((expected_net_edge - net_edge_floor) / 0.60%, 0, 1)
signal_utilization = 0.40 + 0.60 * abs(parent_signal)
round_trip_budget_utilization = sqrt(edge_quality) * signal_utilization
```

预测优势未覆盖成本和净优势底线时，预算使用率为0；只有方向信号和预测净优势都强时才接近完整预算。研究能力总分不进入该公式。

冻结限价在实现周中必须被穿透，刚好触碰不能视为全额成交：

```text
fill_ratio
= clamp(
    penetration_beyond_limit / (realized_weekly_range * 0.20),
    0,
    1
  )
```

入场与目标退出各算一次。目标只部分成交时，剩余已入场数量按周收盘平仓；实际周 K 只在结算时进入穿透公式，不回头改变预算使用率。

### 价差、滑点与高换手的关系

三类磨损分开记账：

- 手续费按 `gross_turnover_lots` 逐边收取，返还也只能基于真实对外总成交；
- 买卖价差是每次从市场获取流动性的固定方向性成本，重复买卖会反复跨越价差；
- 滑点不是固定比例，随单次子订单占当周可用成交量的参与率、当周波动率和执行紧迫度增加。

已经采用的参与率滑点原型为：

```text
participation_rate = child_order_lots / available_weekly_volume_lots

slippage_bps
= min(
    75,
    0.35
    * weekly_volatility
    * 10000
    * sqrt(participation_rate)
    * urgency_multiplier
  )
```

`urgency_multiplier` 随换手活跃从0.85连续升至1.15；周波动率由当周 OHLC 的 Garman–Klass 型估计得到。同一合约、同一周、同一方向的聚合手数作为母单计算冲击，防止只靠拆单消除滑点。换手活跃不再连带改变选择性或调仓反应。

每周先从已实现 K 线形成中性原始成交价，再分别派生现金等价买价与卖价。原始市场成交价必须留在当周已实现高低区间内；外加价差、滑点和费用后的 all-in 价格允许略超出区间，它表达账户现金成本而不是声称市场曾在 K 线外成交。

动态完整价差以主力2 tick、下一主力3 tick、退出旧合约5 tick为基准，按周成交量和波动率调整并限制在1—20 tick。逐边硬费用为交易所1.40美元、清算0.35美元、经纪0.75美元；此前24回合毛成交达到25万／75万／150万手时，可返还交易所费和经纪费的10%／20%／30%，清算费不返还。返还只看本回合之前的历史，不得超过可返还费用，净手续费不得为负。现金结算另收每手0.50美元，不产生市场成交、价差或滑点。

| 执行方式 | 价差成本 | 单笔滑点 | 时点与预测利用 |
|---|---|---|---|
| 低换手 | 跨价次数少 | 单笔较大，参与率可能更高 | 反应慢，持有稳定 |
| 中换手 | 中等 | 可在两周之间分拆 | 平衡时点与磨损 |
| 高换手 | 重复跨价与手续费最多 | 子订单较小时单次冲击可更低，但总冲击不保证更小 | 能更快跟随周度价格与预测区间 |

因此高换手不应被简单加一个更差的固定价格：它的优势是分拆大单、快速修正和更多利用周内路径，代价是更多价差、手续费和错误反复。如果没有短期信号或交易员执行优势，持仓10,000手却周转200,000手应当稳定亏掉价差和费用，不得自动获利。

周度聚合买卖先按经济目的拆成 `net_adjustment` 与 `round_trip`。同一方向的总手数仍作为一个母单计算平方根滑点，再按两类原始名义额精确归因；价差和费用按各自手数归因。最终恒等式为：

```text
gross_pnl_before_cost
= carry_gross_pnl
  + net_adjustment_gross_pnl
  + round_trip_gross_pnl

execution_cost
= net_adjustment_execution_cost
  + round_trip_execution_cost
  + cash_settlement_fee

turn_pnl
= carry_gross_pnl
  + net_adjustment_net_pnl
  + round_trip_net_pnl
  - cash_settlement_fee
```

运行结果同时报告 `raw_average_buy/sell_price` 和 `all_in_buy/sell_price`。账户采用原始市场成交盈亏减现金成本的口径；all-in 价格仅用于显示和对账，不再次进入盈亏公式。`spread_cost_usd`、`slippage_cost_usd`、`gross_fee_usd`、`fee_rebate_usd` 和 `net_fee_usd` 必须逐周、逐合约、逐回合向上汇总一致。

决策截点用最近可见周估算往返总成本，并冻结 `max(换手最小价阶, 估算成本 + 净优势底线)` 作为未来两周的预测价阶门槛。估算成本不能读取未来实现周；实际结算成本、穿透和填充仍使用未来周在结算时才公开的 OHLC 与成交量。

## 交易员与聚合成交价的扩展边界

未来每个实体、每个命名合约、每个周执行窗口只结算一个聚合买价和一个聚合卖价，不恢复逐笔委托。回合结束后再把两个周窗口汇总为半月报告；成交基准只使用对应窗口已经实现的周 OHLC 与周成交量。

当前聚合价格以中性原始成交基准加动态价差和参与率滑点；不区分交易员。以后招募的优秀交易员只能改善价差捕获、冲击系数或紧迫度，但不得凭空提高预测收益、突破成交容量、保证买在最低／卖在最高，或反向影响既定市场路径。

## 最小状态与公式

每个实体、每个命名合约至少维护：

- `position_lots`：回合开始时的带符号净持仓；正数为净多，负数为净空；
- `target_position_lots`：策略希望达到的回合末净持仓；
- `compliant_target_lots`：应用单合约与组合限仓后的目标；
- `target_gap_lots`：`compliant_target_lots - position_lots`；
- `planned_delta_lots`：应用换手速度并优先纳入强制减险后的计划净增减；
- `requested_delta_lots`：完成多合约风险预算分配后，实际提交执行层的净增减；
- `executed_delta_lots`：受本回合成交额度限制后的实际净增减；
- `ending_position_lots`：`position_lots + executed_delta_lots`；
- `unfilled_delta_lots`：本回合未执行、可进入后续回合重新决策的差额。

单合约先裁剪：

```text
compliant_target_i
= clamp(target_position_i, -single_contract_limit_i, +single_contract_limit_i)
```

随后检查四个挂牌合约的组合总持仓：

```text
sum(abs(compliant_target_i)) <= all_contract_gross_position_cap_lots
```

若目标组合超出总上限，只裁剪增加风险的部分；已有的减仓意图不得因为组合裁剪而被撤销。同一优先级可按策略给出的权重或按新增绝对头寸比例分配剩余额度，具体算法在实现前冻结。

单回合净执行：

```text
target_gap_i = compliant_target_i - position_i

planned_delta_i
= required_risk_reduction_i
  + adjustment_speed
    * (target_gap_i - required_risk_reduction_i)

requested_delta_i = allocate_within_portfolio_budget(planned_delta_i)

executed_delta_i
= sign(requested_delta_i)
  * min(abs(requested_delta_i), turn_trade_limit_i)

ending_position_i = position_i + executed_delta_i
```

当前 v0.5.0 中，同一实体、同一合约、同一周窗口的多空子策略先净额化；不同周窗口已经对外成交的买卖不得事后抵销。净调仓和往返交易共同消耗公开毛成交预算，价差、滑点和费用按真实对外毛成交逐项入账，并按经济目的独立报告净利润。

## 多实体聚合

对同一合约，把所有玩家与 AI 的正向净增减合计为买入需求 `B`，负向净增减的绝对值合计为卖出需求 `S`：

```text
internal_match = min(B, S)
residual_market_direction = sign(B - S)
residual_market_demand = abs(B - S)
```

内部匹配的买卖双方都得到成交；市场成交量按匹配手数记一次，不把一手买入和一手卖出重复记成两手。未匹配净需求由模拟市场承接。当前产品边界仍是不让玩家或 AI 改写既定价格、市场成交量、持仓量或宏观路径；聚合执行价、价差和参与率滑点只能按本文路线从只读周行情派生。

## 限额下降与执行优先级

如果市场持仓变化或到期规则使新限仓低于实体当前仓位，风险层把合规目标自动压回新上限，由统一的净增减公式自然生成减仓需求，不另建“平仓额度”。引擎内部执行顺序固定为：

```text
限仓整改
→ 其它降低绝对风险的净变化
→ 增加绝对风险的净变化
```

若本回合成交额度不足，报告必须明确剩余未执行量；未完成整改期间不得继续增加该合约或组合的绝对风险。最终到期现金结算是合约状态转换，不属于市场交易，也不消耗回合成交额度。

## 回合交易报告

界面不需要展示逐笔订单。每个实体、每个合约的最小报告包括：

- 回合开始持仓、策略目标和合规目标；
- 计划净增减、实际净成交和未成交量；
- 两个周窗口的总买入、总卖出、总换手、往返手数和净调仓；
- 回合末净持仓；
- 单合约限仓、组合总限仓与额度使用率；
- 本回合成交额度与使用率；
- 聚合买价、聚合卖价、价差归因、滑点归因、毛手续费、返还、净费用、已实现／未实现盈亏和保证金摘要；
- 是否因单合约限仓、组合限仓、成交额度或到期状态被裁剪。

报告可以把多空混合策略合并成一行，不要求用户理解底层开平标记。

## 非目标

- 不做逐笔委托簿、盘口队列、撤单时序或真实高频撮合；“高频”只是周窗口内的聚合高换手；
- 不拆分开仓成交额度与平仓成交额度；
- 不允许玩家或 AI 反向影响模拟价格、市场成交量、市场持仓量或全球宏观；
- 不把主连当作可交易合约，实际持仓只落在 `OIL-YYMM` 命名合约；
- 正式账户 v0.1 已冻结当前资金规模、静态保证金、追保与强平细则；账户分级、动态保证金、外部注资、跨品种净额和持久存档仍不由本文决定。

## 后续实施门禁

剩余正式实现必须先冻结持仓持久化、跨机构共享容量、组合限仓分配和未成交差额生命周期。现金与保证金单位及账户瀑布已由 `oil_futures_account_v1` 冻结，但确定性重放不能替代正式存档。最低验收包括：

1. 相同 Seed、回合、目标持仓和实体身份得到完全相同的报告；
2. 任一回合末单合约和组合总持仓不因主动增仓越限；
3. 多空跨零、部分成交和未成交结转符合净额公式；
4. 多实体成交守恒，买卖匹配手数不会重复计量；
5. 限仓整改优先于新增风险，并能在报告中追溯；
6. 玩家与 AI 的执行结果不会改写只读市场和宏观 identity。
7. 总买入加总卖出等于总换手，总买入减总卖出等于净调仓，两者均能从周窗口汇总到半月报告；
8. 原始市场成交盈亏只减一次价差、滑点和净费用；all-in 显示价不再次入账，归因字段与最终盈亏无重复扣减。
