# Stage6B-v3：透明报价、逐船装载、货批与已承诺运力

分支 `stage6b-v3-transparent-market`；继承Stage6B-v2 `6f6aaa24e44784ff3eb0538e488636cff5f7d88b`。不修改main、上游原油需求、旧Stage5A/6A及v2计算代码。新入口为 `asset_simulation.model.shipping_v3`。旧代码保留为可重跑对照，不能混用版本。

## 1. 模块与边界

默认海湾、西非→东亚，也可配置原来的四个具名产地。不是全世界，也不是船东公司。仍然统一10运营日/回合、0回合装货、1回合卸货；完整航线货量只进入一份台账，不按船型比例切割。

```
真实船位与冻结航程 + 本回合新货批
 → 完成到期交货
 → 货物台账与当前/已承诺运力曲线
 → 一次性形成解释完整的指示报价
 → 外部逐船装货和压载决策
 → 原子执行并冻结舱单/航程
 → 下一回合重新读取真实状态
```

`types.py`定义数据与配置，`availability.py`重建到船曲线，`pricing.py`只报价，`engine.py`执行货物和船，`policies.py`是可替换测试策略，`checkpoint.py`负责完整恢复，`diagnostics.py`提供不含成本的时间机会比较。

没有同回合“价格→改派→改价格”的循环，没有成本、债务、订船、拆船、货主议价、替代采购或长期需求破坏。

## 2. 逐船指定实际载量

标准能力固定：VLCC 1,971,000桶、Suezmax 985,500桶、Aframax 584,000桶；同一船型不随产地改变能力。外部指令为 `LoadOrder(ship_id, cargo_bbl)`：

```
0 < 实际装载 <= 船型标准能力
总实际装载 <= 真实可装货量
船必须本地开放、兼容，且不能重复出发
```

只装700,000桶的VLCC依然占用完整一艘船及完整航程。实际舱单、交货与参考服务价值按实际桶数记录；不能获得满载参考收益，也不能把航程折成0.355艘船。

默认演示策略先选择最大化完整装载量的组合，每个产地最多再派一艘尾货船，默认最低装载率70%。另测50%与100%。该阈值不是物理限制；外部可以明确让一艘船只装100,000桶。它也不是最低成本策略或现实装载规律。

## 3. 货批拥有独立日期和身份

`CargoBatch`保存批号、产地、目的地、创建回合、计划交付回合、总量、未装量、已交付量。同批可拆给多船，同船可承运多批，`CargoSlice`逐项记录装载来源。

先装最早到期批次，到期相同再按创建时间和稳定ID排序。原始欠运和已完成批次均保留，不按价格压力核销或遗忘。每批总量严格等于未装+在途+已交付。

默认货物计划日期在v3配置中显式规定：海湾3回合、西非4回合、巴西5回合、美湾6回合；外部 `BatchOrder` 可单独指定。日期属于运输任务，不因改用另一船型而改变。慢船迟到会真实表现为计划偏离。

输出区分欠运桶数、最老未装批次年龄、容量加权等待年龄、逾期未装/未交付量和实际交货迟延。“欠34天平均流量”不代表最老一票已经等了34天。

开局在途油用 `bootstrap:` 批次与参考到货配对登记。只有开局前史允许负的产生/出发时间，普通用户回合从0开始。一艘船交货时使用其冻结舱单和装船时的服务基准，不按到达时行情回改。

## 4. 只读取已经确定的未来运力

`A0`是本产地当前兼容开放船的标准载量，`A1/A2`是冻结压载计划明确于下一/下两回合到达的新增载量。它们不是累计船池：每个船号最多出现在一个产地的一个时间桶内。

东亚未承诺空船不分摊给任何产地；载油驶向东亚的船不猜测卸货后去哪。远于观察期的已知到船单列。当前桶以外的船不能装今天的货，也不形成未来订舱合同。

默认权重 `[1,0.5,0.15]`，公开可调。每次从真实位置和MovementPlan重建，不维护另一份会漂移的预测台账。已出发航程不可中途改派；还未提交的外部方案可以改，提交后才进入下一回合的确定到船表。

### 正常供给归一化必须匹配开盘时点

不能把 `A0+0.5A1+0.15A2` 当作一回合额外免费供给，也不能把尚未做出的订单当作缺船。

报价在本回合调船之前形成。若参考压载回程为b回合，开盘时常规已发出订单最多填充h=1至b−1：

```
正常曲线 n(0)=1.06
n(h)=1，当 1<=h<b；否则0
W = Σ weight(h)*actual_arrival_capacity(h)
Z = Σ weight(h)*n(h)
normalized_capacity = W/Z
R = (当前一回合货量+平滑容量)/(normalized_capacity+平滑容量)
```

海湾参考回程2回合，正常曲线为 `[1.06,1,0]`，默认Z=1.56；西非回程3回合，正常曲线 `[1.06,1,1]`，Z=1.71。海湾普通h=2订单尚未产生，不因它为0而认定额外短缺。若更远产地转场等真实计划已经明确h=2抵达海湾，则仍计入分子，不忽略真实证据。

正常曲线采用明确的参考服务回程（VLCC兼容时使用VLCC，否则第一种兼容服务），不是船型配额或未来货量预测。真实船型、航速和路径照各自物理计划执行；不声称这个比较标尺已适用于所有船型结构。解释字段发布参考回程、正常曲线和归一化除数。

在 `A(h)=Q*n(h)` 的常态锚上R=1，35,000美元基准不随观察范围变化。只看当前时Z=1.06。权重和归一化仍属需要校准的游戏规则，可能改变价格水平而不只是平滑波动。

## 5. 价格幅度与欠运紧迫度分开

源端和共享目的地的压力保持±5参考日、3回合半衰期，物理欠运不衰减。市场与紧迫度分别保存0.25惯性：

```
本地供需信号 = 3*ln(R)
共同信号 = 所选航线按参考货量加权的本地信号
局部差异 = 有界、居中的信号残差
TCE = 35,000*exp(市场信号+独立有界欠运信号)
```

局部残差重新居中后再缩放，保证绝对上限与加权和为0同时成立。共同项仍是透明的报价规则，不是船东套利均衡，也不是重复叠加全球缺船。

默认欠运项最大乘数约1.65。它不能仅靠历史欠运把正常35,000推成200,000；但市场真实缺船时，市场项能突破旧122,500上限。

最终只有1—1,000,000美元/标准VLCC日的宽数值保护，命中显式标记，并去掉限幅后隐藏的超额市场记忆。它不是OPEX地板或货主支付上限；本版仍不涵盖负TCE。所有实际值按2025美元生成，再乘最近已结算年度CPI。

## 6. 每条报价都有解释台账

解释包含当前Q、A0/A1/A2及船号证据、权重、正常曲线、归一化容量、平滑项、供需比、共同和局部项、压力及上限、两类历史信号、惯性、最终对数价格、数值保护和CPI。`recompute_price(explanation)`可重新计算最终报价。

船型收益仍为同一每桶净服务价值按容量和参考周期换算，不凭空生成三套船型需求。部分装载参考价值按实际桶数减小，满载TCE单独作为比较值。所有值均不是发票、利润或现金。

## 7. 外部决策、原子执行与恢复

`prepare_turn`处理真实到货和当前货物，返回冻结快照。`settle_turn`只接受匹配快照ID的船级订单，一次性校验并执行。错误方案不会部分修改输入；同一船不能同时载货和压载。

相同快照可以用于离线反事实比较；纯函数接口不是数据库并发锁。正式服务需把状态版本作为条件写入，不能重复持久化同一订单。

明确不出船、不转场也合法。产地闲船仍属于报价供给，不因没有派出就消失。默认演示策略与价格参数独立；更改价格或未来信息权重，不能改变相同外部决策下的物理路径。

`dump_state/load_state`对已结算状态保存全部货批、船号和在途舱单，带版本、spec及内容校验。恢复再运行与未中断路径完全相同。

## 8. 时间机会诊断不混入成本

`time_only_opportunities(snapshot,spec,ship_id)`比较开放船从当前位置压载去产地、再载货回共同目的地的参考服务价值/实际占用时间。所有选项在同一终点比较；从东亚经海湾装货再回东亚是2+3=5回合，不再多加一次标准返程。部分装载降低价值，不缩短航程。

该项不读取未来价格、不算燃油港口OPEX、不参与调船，不能称作利润或无套利均衡。

## 9. 验证

270项完整Python回归，其中48项v3专项；27项Viewer断言。审计25个门槛覆盖守恒、时点、已承诺曲线、正常开盘可知范围、有限溢价、突破旧价限、解释重算、存档恢复与因果前缀。

实际扫描包含5个Seed×3组等/近等总载量船队×20次年度转移，四产地Seed42、两产地60次年度转移；恒定货量50%/70%/100%尾货阈值与开关未来项交叉对照；v2与v3逐项分解；西非单独工作冲击。

具体结果见 `STAGE6B_V3_RESULTS.md`、`STAGE6B_V3_VALIDATION.json`和最终提交CI附件。必须区分所有指示报价、有装运窗口报价、实际载量加权基准。通过守恒或曲线更平滑不等于现实价格弹性校准完成。

外部部分装载：

```python
from asset_simulation.model.shipping_v3 import (
    make_market_spec, initial_market, prepare_turn, settle_turn,
    BatchOrder, Decision, LoadOrder,
)
spec = make_market_spec(origins=('gulf',))
state = initial_market(spec, {'vlcc':1}, initialization='cold')
snapshot = prepare_turn(state, spec,
    new_batches=[BatchOrder('order-001','gulf',700_000,due_turn=3)])
state, record = settle_turn(snapshot, spec,
    Decision(snapshot.snapshot_id, loads=(LoadOrder(1,700_000),)),
    include_events=True)
```
