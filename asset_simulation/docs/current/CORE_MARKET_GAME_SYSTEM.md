# 动态货盘—运力博弈核心系统

> **系统描述世界，但不替世界中的参与者做决定。**
>
> 原油在哪里、船在哪里、库存还能撑多久、船多久能到，这是世界事实；
> 货要不要现在买、从哪里买、船要不要去抢这票货，则是参与者的判断。
>
> 本系统的目标不是求一个“正确答案”，而是让这些判断在同一个物理世界中相互反馈，并留下真实、不可瞬间撤销的后果。

---

## 1. 这套系统是什么

这是一个围绕**货盘、船位、库存、运价与时间滞后**构建的市场博弈核心。

它目前只有两个出口来源、一个进口目的地，但设计本身并不依赖这两个具体航线。当前 Gulf / West Africa → East Asia 只是一个最小可运行原型，用来验证以下更一般的关系：

```text
真实出口能力
+ 真实进口需求
+ 真实库存
+ 真实船位与已承诺未来船位
        ↓
   冻结物理世界
        ↓
货盘试填报 ↔ 运价报价 ↔ 船舶试填报
        ↓
     反复调整
        ↓
   一个最终方案
        ↓
   一次 Final Commit
        ↓
新的真实船位、在途货物与库存路径
```

它既不是传统“给定需求后自动派船”的运输模拟，也不是一个自动求均衡的经济优化器。

更准确地说，它是一套**可重复询问同一个世界“如果这样做会怎样”**的市场内核：

```text
Physical World
      ↓
Frozen Snapshot
      ↓
Counterfactual Trial 1
Counterfactual Trial 2
Counterfactual Trial 3
      ...
      ↓
One Final Commit
      ↓
Physical World'
```

在 Final Commit 以前，所有方案都只是市场意向；在 Final Commit 以后，意向才成为真实历史。

---

## 2. 核心气质：意向同步变化，物理严格异步兑现

这是整个系统最重要的时间观。

### 2.1 同一回合内，市场意向可以近乎同步地变化

货主看到某条航线运费上涨，可以减少该来源订单；船东看到某地货盘变多，可以增加该地船舶填报；新的船舶填报又会重新压低运价；进口方再据此调整货盘。

因此 trial market 中允许：

```text
CargoPlan
    ↕
FreightQuote
    ↕
ShipPlan
```

反复变化。

这模拟的是现实市场中极快的信息反馈：大家几乎同时看到货盘、船位、报价与竞争者意向，并不断修改自己的判断。

### 2.2 但真实世界不会同步瞬移

一艘船今天决定压载去西非，不等于它今天已经在西非。

一票西非原油今天被订下，不等于它今天已经进入东亚库存。

所以系统必须严格区分：

```text
“已经发生”
“已经承诺”
“正在计划”
“尚未表达的可能性”
```

这使市场可以提前 price-in 未来变化，却不能把未来当作现在使用。

例如：

- 当前就在本地并明确参加竞争的船：强烈影响当前报价；
- 当前本地但暂未参战的空船：作为 reserve 形成潜在压力；
- 已提交但尚未开航的转场：作为 proposed future tonnage 被折价计入；
- 已经真实在压载途中的船：作为 committed future tonnage 被计入；
- 在别处、没有表达去向的船：不能被系统猜测成任何市场的未来供给。

这条边界保证了**预期可以交易，物理不能穿越因果**。

## 3. 世界的物理真值

市场机制必须建立在一组不可由报价函数改写的事实之上。

### 3.1 原油来源是真实的

每个出口区只能提供它真实拥有并允许出口的油：

```text
PhysicalAvailable_o
= min(
    当前源端未装油 + 本回合真实释放油,
    当前出口上限
  )
```

如果 Gulf 没油，系统不能因为 East Asia 很缺油就凭空创造 Gulf cargo。

其它来源的油也不能被重新贴标签成 Gulf oil。

### 3.2 进口需求独立存在

目的地的进口义务不是货盘报价函数的产物。

它由独立的 Import Requirement 持有：

```text
需求存在
≠
本回合必须全部形成运输订单
```

需求可以暂时由库存承担时间差，但不能被删除。

### 3.3 库存是缓冲器，不是需求消除器

库存的作用是回答：

> “这批油必须现在运来，还是可以晚一个回合？”

而不是：

> “既然没运来，就把需求取消。”

因此：

```text
Inventory Draw
= 暂缓一部分本期运输
≠ Demand Destruction
```

### 3.4 船舶位置是真实的

一条船同一时刻只能在一个地方、执行一个真实状态。

它不能同时作为 Gulf 和 WAF 的 prompt tonnage，也不能在抵达前装货。

这使船舶成为真正的离散空间资产，而不是一个可以在OD矩阵中任意流动的连续容量数字。

---

## 4. 货盘如何形成

货盘形成层不是“全球炼厂AI”，也不是完整原油贸易模拟器。

它只解决航运游戏必须回答的一个问题：

> **在已有真实需求、真实库存和真实出口能力的情况下，本轮海运订单准备从哪里来、什么时候来？**

### 4.1 Natural Cargo Plan 是自然起点，不是最终命令

上一轮贸易结构、上游OD计划或长期自然流向提供：

```text
NaturalCargoPlan
```

它代表：

> 如果本轮市场没有出现明显反馈，贸易大致会沿什么结构延续。

它提供惯性，但不是硬配额。

所以：

```text
Natural OD ≠ Final OD
```

如果某来源真的缺油，或某来源运力极端紧张，货盘可以改变。

### 4.2 库存焦虑不是开关，而是连续意愿

库存低并不机械意味着“必须立即补货”。

系统把库存状态转换为一个**库存影子运输价值**，用来衡量“再拖一个回合”的代价：

```text
shadow
= freight_anchor × exp(-k × inventory_signal)
```

含义：

- 库存富裕：拖延进口的代价低，更愿意放弃昂贵货盘；
- 库存正常：货盘更接近自然计划；
- 库存偏低：拖延的代价提高，更愿意接受高运费；
- 接近硬库存边界：物理可行性优先，不能靠价格函数把缺口解释掉。

所以真正的关系是：

```text
库存越低
→ willingness to pay for timely shipping 越高
→ 但具体买多少仍取决于来源可用油、相对运费和未来到货时间
```

而不是：

```text
库存低
→ 自动固定补货 X 桶
```

### 4.3 被迫来源短缺与主动补库是两件事

如果自然计划本来需要 5 份 Gulf cargo，但 Gulf 真实只有 2 份，系统先识别：

```text
forced source shortfall
```

如果目的地库存已经偏低，那么恢复原本正常进口总量拥有较高优先级：其它真实来源即使运费偏贵，也应优先承担这部分被迫缺口。

但恢复到自然总进口量以后，是否进一步多买形成库存，则重新由连续的库存意愿函数决定。

这避免了两个极端：

- 一缺油就机械疯狂补库；
- 库存已经很低，却因为替代航线贵而无限继续硬扛。

### 4.4 来源替代由市场反馈决定，而不是人为份额

正式原则是：

```text
不预设“西非最多替代海湾30%”之类现实中并不存在的硬规则。
```

来源替代真正受到：

- 实际可出口油量；
- 当前及未来运力；
- 相对运价；
- 库存焦虑；
- 货物真实到达时间；
- 小步试算后的新报价；

共同约束。

系统不需要知道一个“正确的最终来源比例”。

## 5. 运力如何进入价格

航运价格不只看“最终实际成交了几艘船”。

它还要看市场上有多少真实可竞争吨位。

这使船舶供给被分成几个不同层次：

| 类型 | 含义 | 市场作用 |
|---|---|---|
| Trial tonnage | 当前明确进入该货盘竞争的本地船 | 强当前压力 |
| Reserve tonnage | 当前在本地但没有参加本轮竞争的空船 | 折价潜在压力 |
| Proposed tonnage | 本轮试填报准备未来转场到这里 | 按到达时间折价 |
| Committed tonnage | 已经真实在途中、未来会到达 | 按剩余时间折价 |
| Unknown elsewhere | 在其它地区且未表达去向 | 不猜测、不计入 |

这带来一个非常重要的市场语义：

> **船没有成交，不等于船对市场没有压力。**

如果港口里停着大量空船，货主知道自己有选择，运价自然受压。

反过来，如果未来有大量船已经明确向某地区转场，即使它们今天还不能装货，市场也会开始提前修正对未来紧张程度的判断。

---

## 6. 排队与边际船

货物是连续桶数，船舶却是离散船体。

因此真正的成交分配必须显式处理边际船。

例如：

```text
Cargo = 5.000m bbl
VLCC capacity = 1.971m bbl
```

顺序装载后可能形成：

```text
Ship 1: 1.971m
Ship 2: 1.971m
Ship 3: 1.058m   ← marginal ship
Ship 4: 0
```

第3条船的装载率是真实结果，不应由系统用“70%以下不接”之类隐藏经验规则删除。

船东是否愿意接边际货，属于参与者策略，不属于物理世界规则。

### 6.1 队列机制

未来正式游戏可以采用：

```text
开盘时生成一次可复现随机初始顺序
保持 → 原位置不变
退出 → 从队列删除
新加入 → 队尾
换航线 → 原队列退出，新航线队尾
退出后重进 → 队尾
```

这样顺序影响**谁成交**，而参与竞争的船集合影响**市场多少钱**。

两种机制彼此分离。

## 7. 系统最重要的博弈循环

完整市场循环可以概括成：

```text
真实世界产生局面
        ↓
参与者看到货、船、库存与未来承诺
        ↓
形成货盘与船舶意向
        ↓
市场报价变化
        ↓
参与者重新判断
        ↓
意向继续调整
        ↓
最终有人真正承担风险并 Commit
        ↓
船和油进入真实航程
        ↓
若干回合后后果兑现
        ↓
新世界重新开盘
```

这使游戏核心不再是“找到正确公式”，而是：

> **判断其它参与者会怎样判断这个世界。**

## 8. 可以自然涌现的市场现象

系统真正有价值的地方，不在于它能否复刻某个历史均价，而在于以下现象可以不靠脚本自己出现。

### 8.1 空间价差

如果 Gulf 货少但船多，而 WAF 货突然增加但船仍少：

```text
Gulf freight ↓
WAF freight ↑
```

价差来自：

> 货已经换了地方，船还没有。

### 8.2 羊群拥挤

一条高价航线吸引大量船东加入：

```text
高价
→ 大量船报名
→ 可见竞争吨位上升
→ 报价下跌
→ 后排船东退出
→ 报价回升
→ 又有人重新加入
```

这不是随机事件，而是参与者行为产生的拥挤反馈。

### 8.3 “排队搅局”外部性

一条几乎拿不到货的后排船仍然选择留在市场，只要它是真实可用吨位，就可能继续压低前排船东能够获得的价格。

于是市场会自然出现：

> “你又装不到货，为什么还不走？”

这种冲突不是剧情，而是规则本身产生的利益外部性。

### 8.4 预期先于物理兑现

船东看到某地高价，开始把船压载过去。

船还没到，未来运力已经被市场看到：

```text
future tonnage ↑
→ current expectation of future scarcity ↓
→ price begins to soften before arrival
```

于是可能出现：

> 船还没开到，同行已经把预期价差卷没了。

### 8.5 过冲与反转

大家同时追逐一个短暂高价区域：

```text
高价
→ 大量船转场
→ 若干回合后船集中到达
→ 当地突然供给过剩
→ 运价跌破其它地区
```

这就是典型的物理过冲。

### 8.6 货追船，船追货

进口方看到某来源运价下降，增加该来源货盘；
货盘增加又吸引更多船；
未来船增加又压低价格；
价格变化再次改变货盘。

于是：

```text
Cargo chases tonnage
Tonnage chases cargo
```

没有一个中央调度者需要知道“均衡在哪里”。

### 8.7 库存挤压

库存偏高时，进口方能够等；库存偏低时，等待能力逐步消失。

所以同样一条高价航线，在不同库存状态下会产生完全不同的购买行为。

库存因此不只是安全条，而成为市场博弈里的**时间选择权**。

### 8.8 自我击败的正确判断

玩家可能正确判断：

> “WAF未来会缺船，所以我要先去。”

但如果所有人都做出同一个正确判断：

> WAF未来反而不缺船了。

这是一类非常适合博弈游戏的机制：

```text
一个人的正确判断
≠
所有人同时这么做以后仍然正确
```

## 9. 玩家真正承担的是“位置风险”

这套系统最重要的惩罚不是一个抽象的收益率数字，而是**真实位置错误**。

如果玩家把8条VLCC全部送去WAF，后来市场反转：

- 船已经真实在WAF；
- 回到其它来源需要真实压载时间；
- 这段时间不能瞬间撤销；
- 错误会继续影响后续几个回合。

因此错误会形成一种：

```text
position debt
```

玩家不是“这一回合少赚一点”，而是把未来几个月的选择空间一起押了出去。

这种后果天然制造故事记忆：

> “那年我把整支船队送去了西非，三个月后市场塌了。”

而不需要任何剧情脚本。

---

## 10. 这不是一个自动均衡器

系统明确不做：

```text
argmin global cost
argmax global profit
solve unique market equilibrium
```

当前报价是对真实货盘、真实吨位、库存压力和未来承诺的透明响应函数。

它保证基本方向关系成立，例如：

```text
Cargo ↑ → Freight ↑
Prompt Ships ↑ → Freight ↓
Future Committed Ships ↑ → Future scarcity relief ↑
Inventory ↓ → willingness to secure timely imports ↑
```

但它不宣称：

```text
市场一定收敛
只有一个均衡
所有路线最终价格相等
所有参与者都理性
```

实际上，**不完全收敛、拥挤、反复进入退出、过冲与错误判断本身就是游戏内容。**

---

## 11. 这也不是完整原油贸易模拟器

为了保护核心透明性，本层暂时不模拟：

- 原油grade；
- 炼厂复杂度与原油适配；
- Brent / Dubai / WTI价差；
- term contract；
- trader book；
- 炼厂利润；
- 船东成本与财务杠杆；
- 企业破产；
- 自动船东人格；
- 自动出口国策略。

这些未来都可以成为参与者约束或上层Agent输入，但不能反过来污染底层物理真值。

---

## 12. 游戏设计上为什么它可以独立成为核心玩法

优秀的博弈系统通常需要同时具备：

1. **信息可理解**：玩家知道大致为什么发生；
2. **结果不可完全算死**：其它参与者也在反应；
3. **动作有反馈**：自己的行为会改变局面；
4. **错误有持续后果**：不是一键撤销；
5. **短期与长期冲突**：眼前高价不一定值得追；
6. **局面可重复但结果不重复**：同样规则可以长出不同历史。

这套货盘—运力系统天然满足这几个条件。

玩家面对的不是：

> “这条航线利润率是多少？”

而是：

> “现在这里看起来最好，但别人也看得到。我如果现在进去，等船真正到的时候，它还会好吗？”

这已经足以成为一款博弈类模拟游戏的主要决策循环。

---

## 13. 标准局长度与节奏

当前物理时钟是：

```text
10 operating days / turn
36 turns / year
```

如果标准局设为10年：

```text
360 turns
```

这已经足以经历多轮：

```text
错配
→ 价差
→ 追逐
→ 拥挤
→ 过冲
→ 修正
```

而一条远洋船的完整空间循环需要若干回合，因此玩家的重大判断不会被下一回合立即抹平。

60年更适合作为Sandbox / Infinite模式；10年更适合标准博弈局，因为它足够长到形成路径依赖，又足够短到让玩家记得自己的重大决策。

## 14. 数值调校的真正目标

机制已经成立以后，数值调整不应首先追求“均价完全拟合现实”。

更重要的是校准**反馈增益与时间尺度**。

### 14.1 单个边际动作应该“有感觉但不翻天”

需要观察：

```text
增加1条VLCC → 运价变化多少？
移动250k bbl货盘 → 运价变化多少？
库存少1个flow-day → 补货意愿变化多少？
```

如果一个小动作就导致价格翻倍，系统会变成噪声放大器；如果完全没感觉，玩家又不会认为自己真的参与市场。

### 14.2 预期变化与物理兑现需要不同速度

市场报价可以当回合变化；
船舶真实位置与进口库存必须经过航程才能变化。

这个速度差正是战略深度的来源。

### 14.3 允许偶发过冲，不允许机械振荡

理想状态不是完全平滑。

偶尔出现：

```text
大家追WAF
→ WAF三个月后船太多
→ 运价反转
```

是精彩的。

但如果系统每两回合固定在 Gulf / WAF 之间100%来回摆动，则说明反馈增益过强或阻尼不足。

### 14.4 需要记录的调参指标

未来建议重点观察：

- 每次单船加入造成的报价弹性；
- 每250k桶货盘变化的报价弹性；
- 库存不同区间的货盘响应斜率；
- 船位转场后价格提前反应程度；
- 进入/退出队列频率；
- 来源切换频率；
- 货盘与船位的自相关时间；
- 过冲持续回合数；
- 边际船平均装载率；
- 不同Seed下价差持续时间。

这些指标比单个平均TCE更能说明“游戏是否好玩”。

---

## 15. 信息展示原则

这类系统一旦UI不透明，就会被玩家理解成“系统作弊”。

玩家至少应能看到：

- 当前来源真实可出口油；
- 当前自然货盘与最终trial货盘；
- 当前目的地库存及软/硬区间；
- 未来若干回合库存投影；
- 当前prompt tonnage；
- reserve tonnage；
- proposed / committed future tonnage；
- 当前边际船与装载率；
- 当前试填报顺序；
- 各路线报价；
- 本次货盘调整是来源切换、库存延期还是补库；
- 如果增加/撤走一条船，新的trial quote是什么。

理想的信息状态是：

> 玩家能解释市场为什么大致这样，但不能精确知道其它参与者下一步会怎样。

**世界应透明，参与者不必透明。**

---

## 16. 未来扩展时必须保护的边界

这套系统未来可以扩展：

- Gulf / WAF / Brazil-Guyana / US Gulf 等更多出口区；
- East Asia / South Asia / Europe / North America 等更多进口区；
- VLCC / Suezmax / Aframax全球共享船池；
- 多目的地库存；
- 玩家与AI船东；
- 船舶成本与资产负债表；
- 长期合同；
- 不完全信息；
- 供应中断、战争、港口拥堵等事件。

但扩展时应守住四条底线：

### 16.1 Freight 不能由 Cost 机械决定

成本影响船东愿不愿意接，而不是直接替市场报价。

### 16.2 Agent 不能改写 Physical Truth

Agent可以选择行动，但不能让不存在的油、尚未到达的船或未来到货提前出现。

### 16.3 不用隐藏配额制造“合理贸易流”

如果世界真的会因为模型缺少原油grade而产生极端来源切换，应明确补上grade等真实摩擦，而不是偷偷加一个“最多替代30%”。

### 16.4 不为了看起来稳定而强制求均衡

市场的错误、拥挤、过冲与暂时失衡是玩法，不是必须消灭的bug。

## 17. 当前最小原型已经证明了什么

虽然目前只有 Gulf 和 West Africa 两个来源、East Asia 一个目的地，但最小原型已经证明：

```text
来源真实短缺
→ 货盘能够转向其它真实来源或库存缓冲

库存高低不同
→ 同样运价环境产生不同进口意愿

船舶当前填报不同
→ 运价不同
→ 最终货盘也会反向改变

未来转场船增加
→ 可以提前影响预期
→ 但不能提前参与当前装货

反复试算
→ 不改变任何真实状态

最终 Commit
→ 才真正创造历史
```

因此当前原型虽然地图很小，但已经具备了完整机制的核心因果闭环。

---

## 18. 一句话总结

这套系统真正想模拟的不是“航运价格”，而是：

> **有限的油、有限的船、有限的库存与不可压缩的航行时间，如何迫使一群彼此观察、彼此影响、又无法预知他人最终行为的参与者不断重新判断世界。**

价格只是这个过程留下的信号。

货盘只是参与者此刻的意愿。

船位与库存才是历史真正留下来的东西。

因此这套系统的核心并不是：

```text
找到一个均衡
```

而是：

```text
让局面不断生成新的判断，
让判断改变局面，
让最终承担风险的判断成为不可撤销的现实。
```

这就是整个市场博弈系统最值得保留的气质。
