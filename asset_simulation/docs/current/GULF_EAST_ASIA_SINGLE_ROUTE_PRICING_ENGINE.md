# 海湾→东亚单航线供需定价引擎

> 分支：`gulf-east-asia-single-route-pricing-engine`  
> 模型：`asset-simulation-gulf-east-asia-single-route-pricing-v0.2.0`  
> 状态：实验；不进入 `main`

## 一、这次重构解决什么

这一版把此前的“单一船东运营模型”进一步拆开，只保留一个纯粹的航线定价核心：

```text
本回合海湾→东亚原油运输需求
+ 本回合海湾 prompt VLCC 供给
+ 海湾/东亚相对库存偏离
+ 上一回合市场价格
                 ↓
           单航线定价引擎
                 ↓
实际 TCE（2025年美元）
+ 名义 TCE（当期美元）
+ 紧张度与库存诊断
```

它不再知道：

- 船东是谁；
- 是否存在垄断者；
- 船东选择停多少船；
- 燃油、港口、佣金和 OPEX；
- 船值、折旧、债务和利息；
- 毛运费收入与公司现金流；
- 新船、拆船和资产交易；
- owner/charterer 逐票议价。

因此这一版的边界非常明确：

\[
\boxed{\text{供需与库存决定市场价格}}
\]

以后另一个模块再负责：

\[
\boxed{\text{市场价格与成本决定船东盈亏}}
\]

## 二、输入契约

核心函数 `price_single_route_turn(...)` 每回合只接收：

| 输入 | 含义 |
|---|---|
| `structural_cargo_mbd` | 该回合的海湾→东亚结构货量，mb/d |
| `turn_days` | 本 shipping turn 的实际日数 |
| `prompt_supply_vlcc` | 本回合海湾可立即承接货盘的 VLCC 数量 |
| `origin_inventory_deviation_mmbbl` | 海湾库存相对正常管线的偏离 |
| `destination_inventory_deviation_mmbbl` | 东亚库存相对正常管线的偏离 |
| `previous_real_tce_2025_usd_per_day` | 上回合实际 TCE，用于价格惯性 |
| `cpi_price_level_index_2025_100` | 当期 CPI 价格水平，用于名义化 |

其中 `prompt_supply_vlcc` 必须由外部船队/船位模块提供。定价模块不会自己调船，也不会凭价格生成新船。

## 三、航程时间原则

虽然本模块不负责移动船舶，但它固定了一套供给模块必须遵守的状态契约：

```text
GULF_PROMPT
→ 即时装货，不消耗单独回合
→ LADEN_1
→ LADEN_2
→ EAST_ASIA_DISCHARGE
→ BALLAST_1
→ BALLAST_2
→ GULF_PROMPT
```

即：

| 阶段 | 回合数 |
|---|---:|
| 装货 | 0 |
| 重载航行 | 2 |
| 东亚卸货/周转 | 1 |
| 压载返航 | 2 |
| 完整循环 | 5 |

货物在派船后的第 3 个 shipping turn 进入东亚库存。

这样实现了已经确定的原则：

\[
\boxed{\text{装货不耗时，卸货耗时1回合}}
\]

船一旦在海湾装货离港，在完成卸货之前不再参与任何其他货盘或运力选择。

## 四、库存口径

库存仍然不是绝对区域库存，而是相对于正常贸易管线的偏离：

- 海湾正值：相对积压；
- 东亚负值：相对短缺；
- 零值：恰好处于正常运输进度。

为避免把同一批未运输原油重复计算两次，航线库存缺口定义为：

\[
I_t=\frac{G_t-E_t}{2}
\]

其中：

- \(G_t\)：海湾库存偏离；
- \(E_t\)：东亚库存偏离。

再换算为正常流量天数：

\[
I^{days}_t=\frac{I_t}{Q_t}
\]

如果海湾多 9.3 百万桶、东亚少 9.3 百万桶，而结构流量为 9.3 mb/d，则库存错配是 1 天，不是 2 天。

## 五、库存如何进入当期运输需求

本模型没有另建 backlog 台账。库存只产生一个有上限的“恢复正常管线”需求：

\[
Q^{pricing}_t
=
Q^{structural}_t
+
\operatorname{clip}
\left(
\rho I_t,
-\bar cQ^{structural}_t,
+\bar cQ^{structural}_t
\right)
\]

当前参数：

- 每回合尝试修复库存缺口的 25%；
- 单回合纠偏最多等于结构货量的 20%。

所以：

- 海湾积压、东亚短缺时，定价需求高于结构货量；
- 海湾偏低、东亚偏高时，定价需求可以低于结构货量；
- 不会因为一次库存异常把下一回合需求无限放大。

这不是一层独立“市场需求”，而是把库存恢复所需运力折算进当期船货紧张度。

## 六、船货紧张度

定价需求先换算为 VLCC 等效货盘：

\[
D_t^{VLCC}
=
\frac{Q_t^{pricing}}{1.971\ \text{mmbbl}}
\]

然后与海湾 prompt 船数比较。

为了避免 0 船或小幅整数变化造成数值爆炸，使用带流动性平滑的比值：

\[
R_t
=
\frac{D_t^{VLCC}+s}
     {S_t^{prompt}+s}
\]

其中 \(s=4\) 艘。

价格不直接使用绝对 \(R_t\)，而是相对于参考市场：

\[
\widetilde R_t
=
\frac{R_t}{R_{reference}}
\]

参考市场为：

- 9.3 mb/d；
- 平均每回合约 10.14 天；
- 50 艘 prompt VLCC；
- TCE 35,000 美元/日（2025年购买力）。

50 艘 prompt 船不是全球或完整循环船队，而是当前货盘窗口可见的海湾可用船。

## 七、定价公式

原始价格信号为：

\[
x_t
=
\alpha\ln\widetilde R_t
+
\gamma I^{days}_t
\]

当前：

\[
\alpha=3.0,\qquad\gamma=0.03
\]

库存直接紧迫度项很小，主要作用仍然通过库存恢复需求改变船货比，避免库存被重复计价。

加入价格惯性：

\[
\hat x_t
=
\phi\ln\frac{TCE_{t-1}}{TCE_0}
+
(1-\phi)x_t
\]

其中：

\[
\phi=0.25
\]

实际 TCE：

\[
TCE^{real}_t
=
TCE_0e^{\hat x_t}
\]

并保留实验护栏：

\[
1,000
\le
TCE^{real}_t
\le
122,500
\]

单位均为 2025 年美元/日。

最后名义化：

\[
TCE^{nominal}_t
=
TCE^{real}_t
\frac{CPI_t}{100}
\]

上限仍是原型的数值护栏，不是长期经济学意义上的绝对上限。

## 八、输出

核心引擎输出：

- 结构货量；
- 定价货量；
- VLCC 等效货盘需求；
- prompt VLCC 供给；
- 参考、观察与相对紧张度；
- 海湾—东亚库存错配及天数；
- 原始和带惯性的价格信号；
- 实际 TCE；
- 名义 TCE；
- 是否触及价格护栏。

它明确不输出：

```text
bunker
port cost
commission
OPEX
gross freight
operating margin
cash flow
debt
interest
depreciation
ship value
```

后续成本模块可以读取 TCE，但不能反过来污染这一版供需价格函数。

## 九、Seed 验证适配器

为了测试现有真实 Seed 需求路径，分支包含一个外部供给适配器：

```text
现有 oil_shipping_world 的 gulf_east_asia.cargo_mbd
→ 每月拆成3个 shipping turns
→ 用滞后2回合的需求构造中性 prompt supply
→ 可临时加减若干 prompt VLCC
→ 调用纯定价引擎
```

该适配器只是测试工具，不属于定价公式。以后逐船状态机只需替换它，并持续发布：

```text
prompt_supply_vlcc
```

核心定价函数无需修改。

## 十、模块边界

最终推荐的完整系统边界是：

```text
[原油物理世界]
生成 route cargo demand
          ↓
[船舶状态与船位模块]
0装货 + 2重载 + 1卸货 + 2压载
发布 Gulf prompt VLCC
          ↓
[本分支：单航线定价引擎]
需求 + prompt supply + 库存 → TCE
          ↓
[未来：航次与公司成本模块]
TCE + bunker + port + commission + OPEX
→ 毛运费、运营利润与现金流
```

这次分割的目的就是让每个模块只有一个责任：

- 需求模块回答“有多少油需要运”；
- 船队模块回答“现在有多少船能接”；
- 定价模块回答“这个船货状态值多少钱”；
- 成本模块回答“这个价格下船东赚不赚钱”。

## 十一、自动化验证

GitHub Actions 已实际执行：

- 10 个单元测试；
- 单回合供给单调性测试；
- 库存压力方向测试；
- CPI 名义化测试；
- 输出字段无成本/公司财务泄漏测试；
- 航程状态契约测试；
- 实际 Seed 需求读取测试；
- 虚拟库存守恒测试；
- 临时减少或增加 6 艘 prompt VLCC 的价格压力测试；
- Seed `0,1,5,7,42` 各 20 年审计。

所有测试和审计门槛通过。

### 11.1 单回合敏感度

在 9.3 mb/d、10 天回合、库存偏离为零时：

| 海湾 prompt VLCC | 实际 TCE，2025 美元/日 |
|---:|---:|
| 56 | 26,834 |
| 50 | 34,012 |
| 44 | 44,333 |

这里 50 艘对应的是约 10.14 天平均回合的参考锚；10 天回合略短，因此报价略低于 35,000 美元基准。

在 prompt supply 仍为 50 艘时，若出现：

```text
海湾库存偏离 +9.3 mmbbl
东亚库存偏离 -9.3 mmbbl
```

即 1 天航线库存错配，实际 TCE 从约 34,012 升至：

```text
36,616 USD/day
```

说明供给、需求和库存方向均符合预期。

### 11.2 五个 Seed 的普通路径

测试适配器令 prompt supply 对实际需求滞后 2 个 shipping turns，并保留约 3 艘正常可见船位缓冲。五个 Seed 的普通 20 年路径均满足：

```text
库存严格守恒
普通路径不触及122,500美元上限
供给减少时价格上升
供给增加时价格下降
```

五个 Seed 的实际 TCE P95 约为：

```text
45.4k–46.1k USD/day
```

单回合最高值约为：

```text
49.5k–51.3k USD/day
```

最大库存错配约为：

```text
2.03–2.23天正常流量
```

### 11.3 seed42 普通路径

seed42 的结构货量：

```text
最小 8.188 mb/d
平均 9.443 mb/d
最大 10.904 mb/d
```

测试适配器生成的 prompt supply：

```text
最小 42艘
平均 50.80艘
最大 62艘
```

实际 TCE：

| 指标 | 结果 |
|---|---:|
| P05 | 29,544 USD/day |
| 中位数 | 37,651 USD/day |
| P95 | 46,096 USD/day |
| 最小值 | 22,432 USD/day |
| 最大值 | 50,754 USD/day |

库存错配：

| 指标 | 结果 |
|---|---:|
| P95 | 1.551天 |
| 最大值 | 2.234天 |

20 年 756 个回合中，共出现 626 个未立即完成的整船货盘和 1,657 个未使用 prompt 船位。二者会在不同回合同时出现，反映的是两回合供给响应时滞、整数货盘和库存修复，而不是一条长期固定缺船的航线。

### 11.4 临时供给冲击

在 seed42 的同一需求路径中，连续 9 个 shipping turns、约 3 个月减少 6 艘 prompt VLCC：

| 指标 | 普通路径 | 少6艘 prompt |
|---|---:|---:|
| 实际 TCE 中位数 | 37,651 | 37,818 |
| 实际 TCE P95 | 46,096 | 48,430 |
| 实际 TCE 最大值 | 50,754 | 99,607 |
| 最大库存错配 | 2.234天 | 7.744天 |
| 累计未完成货盘 | 626 | 724 |

峰值接近 100,000 美元，是因为约 12% 的 prompt supply 缺口连续维持 3 个月，库存压力逐步累积；它不是由成本、垄断策略或资本周期产生的。价格仍未触及 122,500 美元护栏。

反向增加 6 艘 prompt VLCC 时，局部最低实际 TCE 降至约：

```text
17,163 USD/day
```

这一组结果说明定价引擎已经能把“当期船货比”和“持续库存错配”区分开：

- 单回合船少，形成即时价格跳升；
- 缺船持续，库存开始累积并放大尾部；
- 船位恢复后，价格通过 25% 惯性逐步回落。

## 十二、当前校准边界

这一版通过的是结构验证，不是最终现实参数校准。

特别是：

```text
连续9回合少6艘 prompt VLCC
→ 峰值约99.6k USD/day
```

这个方向合理，但幅度仍需以后用 TD3C 的历史 fixture、可用船位和库存压力数据校准。当前最重要的成果是模块边界已经稳定：

\[
\boxed{
Demand_t,\ PromptSupply_t,\ Inventory_t
\longrightarrow
TCE_t
}
\]

成本和公司财务可以在完全不改动这个接口的情况下另行接入。
