# Stage6C-preview：动态航运填报与试算市场

本分支 `stage6c-preview-dynamic-freight-board` 从 Stage6B-v3 的 `c89f735ed06154e2309288ed5b941c5457e34909` 继承。不修改 main，不删除6B-v3，不恢复旧成本/垄断模型。实现入口：`asset_simulation.model.freight_board`。

## 1. 本版完成的范围

仍是海湾、西非两个产地到同一个东亚目的地。三种船型共享每条路线的一份货；船型比例不是配置配额。10运营日/回合、装货0回合、卸货1回合和在途航程冻结原则不变。

```
独立源端实际供给 + 独立进口需求/期限 + 已存在的真实船货状态
    → open_turn，冻结一个BoardSnapshot
    → quote_trial(A)，显示价格、满载/边际/未用船、库存可行性
    → quote_trial(B)，回到同一快照重新计算，不继承A的试算结果
    → 任意多次试填报
    → 外部选择一个最终方案
    → commit，冻结最后方案的报价、舱单和真实MovementPlan
    → 推进一个10日回合
```

Board没有任何 `argmin`/`argmax`、船东行为、成本判断或自动买方改订单。回归审计中的外部调用者仅提供预先声明的机械输入，不能把其结果当作市场自主收敛。

## 2. 模块职责

| 文件 | 职责 |
|---|---|
| `freight_board/types.py` | 不可变快照、试算方案、源端和目的地库存区间、独立进口义务 |
| `freight_board/board.py` | 开盘、按顺序计算边际装载、纯试算、v3物理执行适配 |
| `freight_board/pricing.py` | 投入/储备/未来运力→路线服务价值→船型与实际装载参考值 |
| `freight_board/inventory.py` | 真实供给、库存和按到达日期展开的可行性检查 |
| `freight_board/session.py` | 单一状态所有者的原子提交、重复防护和存档 |
| `audit_stage6c_preview.py` | 静态试填报对照、实际Seed外部输入回放，非运行策略 |

旧6B-v3代码没有改写。最终提交通过一个明确、版本固定的适配层，将最终试算报价交给原有 `settle_turn`，沿用它的逐船舱单、FIFO货批、冻结航程和桶数校验。该适配层目前使用v3内部的快照指纹函数，未来升级v3时应一起验证，不应假设跨任意版本兼容。

## 3. 实际油、运输意向与进口需求是三个不同输入

`source_release_bbl` 是本回合实际在各产地释放的油。只有commit才登记成新的真实CargoBatch。它不随trial改动。

`trial_cargo_plan` 是本回合希望从各产地装走多少。它可以使用已有源端库存，但不能超过该产地真实剩余油加本回合释放量，也不能超过调用者另行提供的出口限额。

`ImportRequirement(id,due_turn,volume_bbl)` 是目的地独立的到期需求。改变海湾/西非的trial订单，不会改变这份需求，也不会把未完成需求删除。

例如减少西非订单、增加海湾订单，是改用海湾真实已有的油；绝不是把西非的CargoBatch改个origin后搬过去。西非未装油仍在西非库存。Preview不设OD替代比例，但物理位置和数量是约束。

由于只有一个目的地，源端CargoBatch仍使用旧v3的目的地标记，便于复用舱单系统。正式多目的地时，源端未分配油与目的地订单应进一步拆成单独关系，不能照搬本版单目的地标签。

## 4. 有顺序的船单，不是装载优化器

每条route传入 `ordered_ship_ids`。按顺序：

```
load_i = min(该船能力, 尚未分配的trial货量)
```

有正装载的前缀船满载；最多一条边际船不满载；其后全部为unused。未分到货的船不生成载货MovementPlan。系统不偷偷排序，也不套用70%最低装载率。

5,000,000桶、4艘VLCC依次投入的结果为：1,971,000、1,971,000、1,058,000、0桶。第3艘装53.6783%，第4艘无货。调用者可撤回、换顺序、改船型后再试算。若最终确认，边际船也占用完整船体和完整航程。

同一艘船不能同时出现在两个源端列表，也不能既试投入载货又试转场。需要空放的船必须从当前真实位置出发，不能作为另一个产地的本轮即时载货船。

## 5. 船多、货多与价格响应

每艘船只归入一种报价证据：

- `trial`：本地当前试投入的船，其标准能力全部计入拥挤程度，未分到货也仍表示参与竞争；
- `reserve`：本地未投入、未试转出的开放船，按公开储备权重price-in；
- `committed`：已有不可更改压载计划的确定到船；
- `proposed`：本次trial新提出的压载计划，仅是本方案成立时的未来运力；
- 未明确去向的目的地空船不猜测分配，超出窗口的到船仅单列。

默认未来权重 `[1,0.5,0.15,0.05]`，即当前及未来三个回合。储备权重0.35。所有数值是可调整的游戏规则，不是现实观测频率。

### 各船型分别归一化，再汇总

为了避免更换船型时仍用VLCC的回程代表全部船，本版按每个实际船型的参考回程构造正常曲线：

```
n_c(0)=1.06
n_c(h)=1，若 1<=h<=该船型参考回程；否则0
Z_c=Σ w(h)n_c(h)
E_c=(T_c + 0.35 R_c + Σ w(h)[A_c(h)+B_c(h)]) / Z_c
E_route=Σ E_c
```

这里是**试提交新压载计划之后**的比较口径，所以正常曲线包含h=回程长度。不能误用v3开盘时点的严格小于号。

先分别除以各自固定的Z，再加总，避免简单重算混合船型公共除数时出现“多加一条船反而涨价”。每种船的回程和循环时长、Z和分子均输出；无论哪种船为主，都不读取旧船型比例。

### 局部报价，不强行拉平价差

```
R=(trial cargo + smoothing)/(E_route + smoothing)
market_log=3*ln(R)+有限库存软压力项
price=35000*exp(一次性惯性后的market_log + 有界近期欠运项)
```

本版默认不继承v3人为的跨产地共同均值。原因是动态订单转移需要可检查的本地反应：同一冻结库存与船单下，增加海湾订单应提高海湾报价，减少西非订单应降低西非报价；不能被另一路共同均值覆盖。共同目的地库存仍同时影响各路线。

这属于有意改变试算报价语义，**不是保持旧v3的价格校准不变**。正确验收是方向、守恒、纯度与最终方案一致，不是要求新旧TCE中位数相同。

## 6. 每桶价格与载货率

仍使用统一每桶净运输服务参考值，明确不是毛运费、发票、利润或现金。参考标准VLCC日收益仅是一个输出标尺。

```
船型满载参考TCE = 每桶服务参考值 × 船型能力 / 该船型参考周期日数
实际装载参考TCE = 每桶服务参考值 × 实际装载 / 该船型参考周期日数
```

部分装载只减少实际服务量，不再对每桶价格二次打折。同一容量/同一时间的1艘VLCC与2艘Suezmax替换，当前纯报价一致。不同路径或时间的替换则按各自物理服务解释，不能硬要求相等。

惯性始终从上一个**已提交**状态读取。试算1000次不会把价格记忆推进1000回合。最终只保留继承的1—1,000,000美元宽数值保护并标记命中，不能据此认定经济最高价已校准。

## 7. 虚拟库存不是可以随意填的数字

本版的虚拟库存是：

```
偏离 = 记录的实际库存 − 显式正常库存
```

源端实际库存来自初始岸上油、本回合真实释放、实际装货。目的地实际库存来自初始库存、**真实到货**、独立到期需求。

初始岸上缓冲是明确的实物初始化输入，而不是开局偷偷借油。开局已经在途的bootstrap货，另配对它的参考进口义务，以免当成免费多到的库存。

源端旧CargoBatch的due日期用于货物追溯与装运顺序；目的地的实际消耗由新的独立ImportRequirement拥有。不能再使用“所选来源的新订单推导需求日期”，否则改来源会改变真实需求。

### 默认区间（游戏假设）

| 节点 | 正常库存 | 负硬边界 | 负软边界 | 正软边界 | 正硬边界 |
|---|---:|---:|---:|---:|---:|
| 各源端 | 20个参考流量日 | -20 | -7 | +20 | +60 |
| 东亚目的地 | 40个参考流量日 | -40 | -10 | +10 | +40 |

除正常库存列，其余均为相对正常库存的偏离。边界可覆盖配置或逐节点输入，不代表现实岸罐规模。

软压力使用连续有界函数，只影响价格。硬边界检查**最终实际装载对应的逐期库存路径**。未被船承运的trial货不能提前计入进口。

投影至少覆盖12回合，以及全部明确已知的到货/需求；单次新增已知需求的支持窗口最多36回合，防止错误输入构造无界投影。未发生的新供给、未知未来需求与未来未提交的排船不会被猜测。

如果已经确定的缺口在当前或下回合发生，而今天派出的船要3回合才到，系统必须报告方案不可行。不能把“已下单”当成“已到货”来通过硬边界。也不能因为硬边界而删除油、削减已登记需求或伪造库存。

`trial_inventory_plan`只可断言预期的某回合库存与实际推算一致，不能授权任意增加库存。

## 8. Commit与一次性执行

`quote_trial` 是纯函数。`BoardSession`拥有真实已结算状态；同一开盘只接受一次成功commit。并发提交通过锁与状态版本检查保证只有一次成功。无效方案不会造成半结算，仍可从原快照重新试算合法方案。

确认时重新验证最终trial，创建本轮全部真实源端释放货批，将最终服务价交给旧v3执行器，只为实际拿到货的船生成舱单/MovementPlan。其余油保持在源端；未用船仍在港；只有实际交货时目的地库存才增加。

存档只允许已结算状态。恢复后保存全部独立需求、源端累计释放、船舶和货批，旧snapshot不能再次提交。这个保证属于**一个状态所有者**；两个独立进程从同一存档恢复是两个模拟分支，正式服务器需要数据库条件写入，不声称本版已有分布式事务。

## 9. 没有自动收敛保证

动态填报的负反馈方向可以测试，不能从“方向正确”推出任意离散策略都会稳定或存在可行配置。大量参与者同时改方向、总运力不足、来源无油、既有在途货即将冲破仓容，都可能产生震荡或无解。

本版只负责公开当前方案的价格、边际位置与约束，不负责替参与者求最优解。硬约束不可行时返回明确错误并拒绝commit，绝不静默放宽边界。全世界的多目的地、集合地区细分和自动买方行为不在本轮实现内。

## 10. 使用

```python
from asset_simulation.model.freight_board import (
    BoardSession, ImportRequirement, make_board_spec, quote_trial,
)

spec = make_board_spec()
board = BoardSession(spec, fleet_counts={'vlcc': 12, 'suezmax': 8, 'aframax': 4},
                     initialization='cold')
snapshot = board.open_turn(
    source_release_bbl={'gulf': 5_000_000, 'west_africa': 1_000_000},
    new_requirements=(ImportRequirement('east-asia-order-1', 4, 6_000_000),),
)
ship_plan = {o: [s.ship_id for s in snapshot.opened_market.ships if s.location == o]
             for o in spec.origins}
a = quote_trial(snapshot, ship_plan, {'gulf': 5_000_000, 'west_africa': 1_000_000})
b = quote_trial(snapshot, ship_plan, {'gulf': 5_500_000, 'west_africa': 500_000})
print(a.report()['routes']['gulf']['route_benchmark_real_tce'])
print(b.report()['routes']['gulf']['allocation'])
assert board.state.market.turn == 0
result = board.commit(b)  # 外部选B；不是系统选择B
assert board.state.market.turn == 1
```
